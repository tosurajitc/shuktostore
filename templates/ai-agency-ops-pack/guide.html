Getting started — open and edit your first template

01

Unzip your download

Open the ZIP file. You'll find 4 HTML files inside. Move them into a folder called AI Agency Ops Pack on your computer — somewhere easy to find, like your Desktop or a client work folder.

02

Open a template in Chrome

Double-click any .html file. It opens in your default browser. For the best PDF output, use Chrome or Edge. Safari on Mac also works well.

03

Click any dashed field to edit

Every field with a dashed underline is editable. Click once, then type. Your agency name, client details, dates, and all content are yours to fill in — nothing is locked.

04

Print / Save as PDF

Click the "🖨 Print / Save as PDF" button at the top of the page. In the print dialog, set Destination → Save as PDF. Keep default margins. The README bar and print button disappear from the PDF automatically.

🗂️
Before filling in any template: duplicate the file first and rename the copy (e.g. onboarding-ClientName.html). Keep the originals blank so you always have a clean base for the next client.

Template 01 — Client Onboarding Brief

Portrait A4 2 pages Client-facing

Use this at the start of every new client engagement. It captures everything you need in one professional 2-page document that both you and the client sign off on — and doubles as your scope reference if disagreements arise later.

When to use it
Fill this before or immediately after your kickoff call, and send it to the client for review and signature before any paid work begins. Think of it as your mutual agreement on what success looks like.
Step-by-step
1
Duplicate the file
Rename it to onboarding-ClientName-2025.html. Keep the original blank for the next client.
2
Fill in the header first
Set your agency name, today's date, a project ID (e.g. PROJ-004), and the status badge.
3
Work through Sections 01–06
Use your discovery call notes. Sections 01–03 capture who the client is and what they want. Section 04 (Scope table) is the most important — be specific about deliverables, owners, and due dates.
4
Complete the onboarding checklist (Section 05)
Tick each box as the onboarding steps are completed during the first week. This section is ongoing — not something to fill in all at once.
5
Print to PDF → send to client
Portrait A4, default margins. Send by email for review and signature before starting any work. Use DocuSign, HelloSign, or print and sign physically.

SectionWhat to enterFill when
01 — Client InfoCompany name, contact, email, phone, website, time zoneKickoff call
02 — Business SnapshotWhat they do, target customer, team size, tech stackDiscovery call
03 — Goals & KPIsPrimary goal, how you'll measure success, timeline, budgetDiscovery call
04 — Scope of WorkDeliverables table — what, who owns it, due date, statusAfter scoping

💡
Scope creep tip: If a client asks for something not in the Scope of Work table, open this brief, point to Section 04, and say "That's outside what we agreed — happy to quote it as a new line." This document protects you.

Template 02 — Prompt Library

Portrait A4 2 pages Agency-wide

Your master reference for every reusable AI prompt across all client work. Keep one copy of this file — it grows over time. When you find a prompt that reliably delivers great output, it goes in here.

When to use it
This is an ongoing living document — not a per-project file. Add to it whenever you discover a prompt that works well. Print a PDF snapshot monthly to archive your library's state.
Step-by-step
1
Keep ONE master file — never per-client copies
Your prompt library is agency-wide. All your team's reusable prompts live here. Don't create separate files per client.
2
Add to the index table (Page 1) first
Give the prompt a sequential ID (P-001, P-002…), name it, tag its category, and note which model works best.
3
Add the detail card (Page 2)
In the browser, right-click an existing card → Inspect → duplicate the HTML block. Fill in the prompt text, variables, rating, and limitations.
4
Update the summary stats (top of Page 1)
The 4 stat boxes show total prompts and per-category counts. Click each number to update it after adding entries.
5
Archive monthly — keep HTML as the live version
Print to PDF once a month as a snapshot. The HTML file is your working document — it stays open and editable in the browser.

Template 03 — Automation Tracker

Landscape A4 1 page Agency-wide

Your single source of truth for every automation running across all client engagements. Track status, ownership, cost, and ROI in one landscape view. Update it monthly or after each deployment.

🖨️ Important: this template prints in Landscape
When printing, open Chrome's print dialog and set Orientation → Landscape. If columns get clipped, enable "Fit to page". Portrait will cut off the right-hand columns.
Step-by-step
1
Keep ONE master file across all clients
Unlike the onboarding brief, this file is not per-client. Every automation you build for any client goes in the same tracker. Use the "Client" column to distinguish them.
2
Add a row for every automation you deploy
Give it an ID (A-001, A-002…), fill in the name, client, category, tool stack, and set the status pill. Add even automations that are just Planned.
3
Update status after each change
Click the status pill text to change it: Live / In Build / Planned / Paused / Error. Keeping this accurate takes 2 minutes and saves hours of "where is that automation?" confusion.
4
Update the ROI summary section monthly
Sum the Time Saved column → enter total. Sum the Monthly Cost column → enter total. Multiply hours by your hourly rate for Value Generated. ROI = (Value − Cost) ÷ Cost × 100.

Template 04 — Project Dashboard

Portrait A4 2 pages Client-facing

A professional weekly or bi-weekly status report you can send directly to clients. It covers everything a client wants to know — progress, what's done, what's next, blockers, and what they need to action — without exposing any internal agency detail.

When to use it
Create a new copy every reporting cycle (weekly or bi-weekly). Do not edit the same file repeatedly — keep each week's report as a permanent record. Name files like dashboard-ClientName-Week3.html
Step-by-step (weekly reporting workflow)
1
Duplicate → rename
Start from your previous week's report or a fresh blank. Rename the file with the client and week number.
2
Update the KPI strip first
Set overall progress %, current day/week, budget spent to date, and count of open blockers. These 4 numbers tell the story at a glance.
3
Update deliverable status pills
Change status pills from "Upcoming" → "In Progress" → "In Review" → "Done" as work moves through your pipeline. Add a note for anything that changed.
4
Advance the milestone dots
Change m-future → m-active → m-done as milestones complete. There should be exactly one m-active dot at any time.
5
Replace Section 05 actions entirely
Delete last week's actions and write only this week's items. Keep agency actions (→) and client actions (!) clearly separated. The yellow highlight draws the client's eye to what they need to do.
6
Print → send to client
Portrait A4, default margins. Email as PDF, or share the link in your Slack / Notion channel if you work that way.

💡
The header status pill is the first thing clients see. Be honest about it — change it to At Risk when something is genuinely at risk. Clients always prefer an early flag over a surprise at go-live. Honest reporting builds more trust than always showing On Track.

General tips

📁
Folder structure that works
Keep the 4 blank originals in one folder. Create a per-client subfolder (e.g. Clients/AcmeCorp/) and duplicate the relevant templates there when you start a new project.
🌐
Best browser for printing
Use Google Chrome for the most accurate PDF output. The print layout is optimised for Chrome. Edge also works well. Safari handles it but may render fonts slightly differently.
✏️
The in-file guides don't print
The coloured README bar at the top of each template (the one you click to expand) is automatically hidden when you print. The print hint bar with the "🖨 Print" button is also hidden. Your PDF will contain only the clean template content.
